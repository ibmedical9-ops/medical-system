# Prompt Trap Lab — مختبر فخاخ البرومبتات

تطبيق ويب عربي (RTL) لتدريب المستخدمين على كتابة تعليمات دقيقة للذكاء الاصطناعي. يحاكي نموذجاً **يستغل الغموض والنقص** في تعليمات المتدرب عند تحليل محاضر الاجتماعات، وينفّذ بدقة حين تكتمل التعليمات.

> **تنبيه صريح:** الوضع الافتراضي «محاكاة محلية» تولّدها قواعد لغوية مبرمجة وليست نموذجاً لغوياً حقيقياً. التقييم الآلي للبرومبت تقريبي ولا يضمن جودة النتيجة مع نموذج حقيقي. المحلل اللغوي للمصدر يعمل جيداً مع جمل عربية صريحة بصيغة «المتحدث: كلامه» وقد يخطئ مع الصياغات الملتوية.

## المتطلبات
- PHP 8.2+ مع `pdo_sqlite` أو `pdo_mysql` و`mbstring` (و`curl` للمزودات الخارجية).
- MySQL 5.7+/MariaDB 10.4+ (اختياري). بدونه يعمل التطبيق على SQLite دون إعداد.

## التشغيل المحلي
```bash
cp .env.example .env            # اختياري؛ الافتراضي SQLite + محاكاة
php bin/install.php             # ينشئ الجداول والسيناريو والمصدر التجريبي
php bin/create_user.php trainer "كلمة-مرور-قوية" "المدرب" trainer   # اختياري: حساب مدرب
php -S 127.0.0.1:8080 -t public # ثم افتح http://127.0.0.1:8080
```
المتدربون يدخلون كضيوف تلقائياً. المدرب يضغط «دخول المدرب» ليرى مفاتيح الإجابة لأي محاولة.

## استخدام MySQL / MariaDB
1. أنشئ القاعدة والجداول: `mysql -u root -p < database/schema.mysql.sql`.
2. في `.env`: `DB_DRIVER=mysql` ثم `DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASS`.
3. `php bin/install.php` لإضافة السيناريو والمصدر التجريبي (أو استورد `database/seed_sample.sql` يدوياً).

## دورة التدريب
1. «بدء تجربة جديدة»: اختر المصدر التجريبي أو الصق محضرك.
2. اكتب برومبتك واضغط «تنفيذ التعليمات». لا تُعرض درجة ولا مفتاح قبل طلبهما.
3. حدّد حكمك (صحيحة/فيها أخطاء) ثم «كشف الأخطاء»: مقارنة بين ما قاله النموذج وما في المصدر (بالاقتباس الحرفي)، والإجابة الصحيحة، والبرومبت المحسّن.
4. «تقييم البرومبت» يعرض درجة 0–100 على سبعة أبعاد. «تحسين البرومبت» يقترح صياغة تغلق الثغرات. «محاولة أخرى» تُسجَّل محاولةً مستقلة وتُقارن بالسابقة.

## المكوّنات (مستقلة عن بعضها)
| المكوّن | الملف | الدور |
|---|---|---|
| محلل المصدر | `src/Domain/MeetingParser.php` | يستخرج قرارات/مقترحات/مهام/نقاطاً مفتوحة/مسؤولين/مواعيد مع دليل حرفي |
| محرك تقييم البرومبت | `src/Domain/PromptAnalyzer.php` | 7 أبعاد؛ لا يعتمد على الطول ولا على عبارات بعينها |
| محرك محاكاة الأخطاء | `src/Domain/ErrorSimulator.php` | 8 أنواع أخطاء، كل خطأ مربوط بثغرة وبمادة في المصدر، حتمي بالبذرة |
| المزود | `src/Ai/*` | واجهة `ProviderInterface` قابلة للتبديل |
| الخدمة والـAPI | `src/Service`, `src/Http`, `public/api.php` | الجلسات، المحاولات، الكشف، الصلاحيات |

القواعد: برومبت ناقص ⇒ تُفتح فخاخ بقدر نقصه فقط وتبقى بنود صحيحة. برومبت مكتمل (درجة ≥ 85 ولا بُعد دون 0.75) ⇒ تنفيذ دقيق. إن لم يقع خطأ فعلي يُسجَّل «لم تتضمن النتيجة خطأً قابلاً للإثبات» ولا يُخترع خطأ. أي اسم/تاريخ/بند مضاف من خارج المصدر يُسجَّل في مفتاح الإجابة.

## مزود الذكاء الاصطناعي
التبديل بالإعدادات فقط (`.env` أو متغيرات البيئة):
```
AI_PROVIDER=simulation | openai_compatible | anthropic
AI_API_KEY=...   AI_MODEL=...   AI_BASE_URL=https://api.openai.com/v1   # أو http://localhost:11434/v1 لـ Ollama
```
- **قرار التصميم:** المحرك المحلي يقرر الأخطاء ويكتب مفتاح الإجابة؛ المزود الخارجي يصيغ البنود المخططة فقط. إن غيّر المحتوى أو فشل الاتصال يُستخدم المولّد المحلي مع ملاحظة، ليبقى المفتاح مطابقاً للمخرجات.
- مع مزود خارجي **تُرسل مقتطفات من نص الاجتماع إلى تلك الخدمة**، وتعرض الواجهة تنبيهاً بذلك.
- المفاتيح لا تظهر في JavaScript ولا الواجهة ولا السجلات؛ `.env` مُستثنى في `.gitignore`.

## الاختبارات
```bash
php tests/run.php
```
تغطي الحالات السبع المطلوبة، والأمان (عدم تسرب المفتاح، الملكية، CSRF، حقن نص الاجتماع)، وتبديل المزود، وربط كل نوع خطأ بثغرته. المحلل والمحاكي يُختبران كلٌّ على حدة. الحالة 2 تستخدم البرومبت الدقيق الكامل؛ جملة قصيرة مثل «استخرج القرارات من المصدر فقط» تُعامل كناقصة عن قصد لأنها لا تغطي المجهول والتمييز والتحقق.

**ما لم يُختبر:** مخطط MySQL لم يُشغَّل على خادم MySQL فعلي (لم يتوفر في بيئة التطوير)؛ الاختبارات على SQLite عبر نفس طبقة PDO. جرّب `schema.mysql.sql` على خادمك أولاً. المزودات الخارجية اختُبرت ببنية الطلب/الاستجابة بنقل وهمي دون اتصال حقيقي.

## الأمان
استعلامات محضّرة؛ الواجهة تُدرج النصوص بـ`textContent` فقط مع CSP صارم؛ جلسات HttpOnly/SameSite؛ CSRF لكل POST؛ `password_hash`؛ تحديد محاولات الدخول؛ جداول `prompt_analyses` و`error_records` و`answer_keys` لا تُقرأ إلا بعد التقييم/الكشف أو للمدرب؛ نص الاجتماع بيانات لا تعليمات؛ لا تُسجَّل المفاتيح ولا المدخلات.

## النقل إلى استضافة
1. ارفع المشروع واجعل **جذر الويب = `public/`** (حتى لا يُكشف `.env` و`src` و`database`).
2. أنشئ قاعدة MySQL، عبّئ `.env`، وشغّل `php bin/install.php` (SSH) أو استورد `schema.mysql.sql` ثم `seed_sample.sql`.
3. فعّل HTTPS (تصبح كوكيز الجلسة `Secure` تلقائياً)، واجعل `storage/` قابلاً للكتابة إن استخدمت SQLite.
4. أنشئ حساب المدرب بـ`bin/create_user.php`.

## افتراضات تقنية
- `api.php?action=` بدل مسارات REST لتعمل على أي استضافة دون إعادة كتابة.
- متدربون ضيوف بجلسة PHP، وحساب مدرب بكلمة مرور؛ لا إدارة مستخدمين عبر الواجهة.
- العربية فقط في تحليل البرومبت والمصدر.
- حدود: المصدر ≤ 20000 حرف، البرومبت ≤ 4000، 50 محاولة لكل تجربة.
